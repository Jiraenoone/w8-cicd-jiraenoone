# w8-cicd-jiraenoone
1. ส่วนใดของงานนี้คือ Continuous Integration?
ส่วนที่เป็น Continuous Integration ของงานนี้คือกระบวนการทำข้อสอบอัตโนมัติในระบบ GitHub Actions ที่ทำการดึงโค้ด ติดตั้งแพ็กเกจ ตรวจสอบโครงสร้างภาษา และรันชุดทดสอบโดยอัตโนมัติทุกครั้งที่มีการกด Push หรือสร้าง Pull Request เข้ามายังระบบ repository

2. งานนี้มี Continuous Delivery หรือ Continuous Deployment แล้วหรือยัง? เพราะเหตุใด?
งานนี้ยังไม่มีทั้ง Continuous Delivery และ Continuous Deployment เนื่องจากในกระบวนการทำงานของไฟล์สคริปต์ยังคงสิ้นสุดอยู่แค่ขั้นตอนการทดสอบและสั่งบิวด์โค้ดเท่านั้น โดยยังไม่มีขั้นตอนการเตรียมสร้างไฟล์พร้อมส่งมอบไปยัง staging หรือขั้นตอนการส่งโค้ดขึ้นไปประมวลผลบนเซิร์ฟเวอร์หรือคลาวด์จริงโดยอัตโนมัติ

3. Green pipeline ยืนยันอะไรได้บ้าง และยืนยันอะไรไม่ได้?
Green pipeline ยืนยันได้เพียงว่าโค้ดสามารถสั่งบิวด์ผ่านโดยไม่มีข้อผิดพลาดทางไวยากรณ์และทำงานผ่านชุดทดสอบทั้งหมดตามที่ผู้พัฒนาได้เขียนระบุไว้ แต่ไม่สามารถยืนยันได้ว่าแอปพลิเคชันจะไม่มีข้อผิดพลาดหลงเหลืออยู่เลย ไม่สามารถยืนยันความปลอดภัย ตลอดจนไม่สามารถรับรองได้ว่าการแสดงผลและตรรกะทางธุรกิจจะตอบโจทย์ผู้ใช้งานจริงได้ครบถ้วน หากเขียนชุดทดสอบไว้ไม่ครอบคลุม

4. เหตุใดเราจึงต้องทดลองสร้าง red pipeline?
เราต้องทดลองสร้าง red pipeline เพื่อพิสูจน์ให้มั่นใจว่าระบบการทดสอบอัตโนมัติสามารถตรวจจับและแจ้งเตือนความผิดพลาดได้อย่างถูกต้องจริง ไม่ใช่การรันผ่านปลอมๆ และเพื่อให้มั่นใจว่าเมื่อมีโค้ดที่มีข้อผิดพลาดถูกส่งเข้ามาในระบบ ตัว pipeline จะสามารถยับยั้งไม่ให้โค้ดส่วนที่มีปัญหาถูกรวมเข้าสู่ branch หลักได้อย่างรวดเร็ว

5. หาก test ผ่านแต่ application ใช้งานจริงไม่ได้ ควรเพิ่ม test หรือ pipeline stage ใด?
หากชุดทดสอบผ่านแต่แอปพลิเคชันใช้งานจริงไม่ได้ ควรเพิ่มการทดสอบแบบ Integration Test เพื่อตรวจสอบการเชื่อมต่อกับระบบภายนอก เพิ่มการทดสอบแบบ End-to-End Test ในการจำลองพฤติกรรมการใช้งานของผู้ใช้จริงบนเบราว์เซอร์ พร้อมทั้งเพิ่มขั้นตอน Smoke Test หรือ Health Check หลังจากทำการปรับแต่งสภาพแวดล้อมระบบเพื่อตรวจสอบการตั้งค่าและเช็กว่าแอปพลิเคชันเปิดทำงานได้จริงหรือไม่
